# Working on open-infra

Instructions for anyone — person or coding agent — changing this repository. [CONTRIBUTING.md](CONTRIBUTING.md)
has the ground rules; this file is the definition of done.

open-infra serves AWS's APIs on infrastructure you own. Its customer is an AWS user, not a Kubernetes
operator. The guiding rule for every decision: **do it like AWS** — pick what AWS does, not an invention.

## A feature is AWS-shaped from day one

A feature counts as landed only when it ships, in the same change, with all five:

1. **AWS's API shape.** The AWS service, its operations, ARNs and error codes, as AWS names them. A
   platform-only capability gets its own AWS-style API (`openinfra:<Action>` on
   `arn:aws:openinfra:<region>:<account>:<type>/<name>`), and only on the operator's say-so, recorded in
   `probe/registry/surface.yaml`.
2. **IAM actions, decided by the one evaluator, with a deny case tested.** Every door — a console route,
   the console's resource API, an aws-shim front door — asks `internal/iamauthz` for an IAM action on an
   ARN, and a test shows it refusing a principal its policy does not allow.
3. **A coverage registry entry.** The service in `probe/shim-services.yaml`; the registry under
   `probe/registry/` regenerated by `python3 probe/shimgen.py` and committed.
4. **AWS vocabulary on every customer surface.** The console and the user docs speak AWS: no namespaces,
   claims, `kubectl`, or Kubernetes errors. Operator guides are the exception, and say so.
5. **A live probe through the AWS surface, including a denial.** `probe/aws-shim-<name>.sh`, run with the
   real AWS CLI or SDK, asserting at least one call refused with AWS's access-denied error. A probe that
   has not yet passed live is `pending`, never proof.

Kubernetes is not a customer surface: tenants get no Kubernetes access. Choke the doors, not the
features — a capability Kubernetes has that the AWS surface does not express is either given an AWS
shape, made a platform extra with the operator's approval, kept the operator's alone, or removed.

## What CI enforces

`.github/workflows/test.yml` fails a change that misses these, mechanically:

| Gate | Fails when |
|---|---|
| `console-api/internal/awsaction` (`TestEveryPlatformKindIsMapped`, `TestActionsAreAWSDocumented`, `TestIAMActionsRegistryIsCurrent`) | a claim kind has no row of IAM actions, an action is not one AWS documents, or `probe/registry/iam-actions.json` is stale |
| `console-api/cmd/server` (`TestConsoleRoutes_EveryRouteHasAnIAMAction`, `TestConsoleRoutes_EveryGatedRouteDeniesWithoutPolicy`, `TestConsoleRouteRegistryIsCurrent`, `TestTenantKubernetesAccessIsRefused`) | a console route has no IAM action, a gated route does not refuse a principal with no policy, `probe/registry/console-routes.json` is stale, or a tenant reaches a raw Kubernetes object |
| `console-api/cmd/aws-shim` (`TestEveryFrontDoorHasADenyCase`, `TestEveryLegacyCheckRunsOnlyAsALegacyDecision`, `TestCoverageRegistryShimRouter`) | a front door has no enforce-mode deny case, an authorization check runs outside `decide`, or `probe/registry/shim-router.json` is stale |
| `python3 probe/shimgen.py --check` | a service is not in the registry, a proven service has no probe or no probe asserting a denial, the router serves a service `probe/iam-no-policy.sh` does not call, a claim kind, field, route or screen has no AWS-shaped entry in `probe/registry/customer-surface.json`, or a generated doc is stale |
| `python3 probe/test_coverage.py`, `python3 probe/test_surface.py` | the gates above stop going red on a deliberately unregistered capability |
| `python3 docs/openapi/generate.py --check` | an XRD changed without regenerating the platform OpenAPI spec |

`docs/customer-surface.md` is the inventory of everything a customer can reach, generated by the same
command.

## Working here

- Run what you touch: `go vet ./... && go test ./...` in each Go module you changed (console-api's
  store-backed tests take `OPENINFRA_TEST_PG_URI`, a throwaway Postgres), `python3 probe/shimgen.py`
  then `--check`, `python3 docs/openapi/generate.py --check`, and the Python tests under `probe/`.
- The repository is public: no real hostnames, LAN addresses, private tracker references or customer
  names, in code, docs or commit messages. Site values belong in `config.yaml` (gitignored).
- README, CHANGELOG and `docs/` are product documentation: what the software does and its honest status,
  never a development journal.
