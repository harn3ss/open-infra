# AWS coverage — CloudFormation types and the aws-shim front doors

open-infra speaks AWS two ways: the [`cfn` engine](cloudformation.md) creates resources from a
CloudFormation template, and the [aws-shim](aws-shim.md) serves AWS APIs over the same resources. The
two have to agree. If a stack creates a queue, an application must be able to find that queue through
the SQS API, by the name the stack reports. This page is the registry that holds the two in step. Every
table on it is generated from code, and CI fails when they disagree.

## The front-door gate

For every resource type a stack can create (its mapping is supported or partial **and** it has a create
translator — the same `Deployable` fact `cfn plan` reports), CI requires:

1. **a front door for its own API.** The aws-shim router serves the SigV4 signing name of the type's
   API (`AWS::SQS::Queue` → `sqs`). Without one, the stack's resource cannot be found through AWS at all.
2. **a call that reads it.** That front door serves at least one `Describe`/`Get`/`List`/`Head` call
   for the type (for `AWS::SQS::Queue`, `GetQueueUrl`, `GetQueueAttributes` or `ListQueues`).

A type that fails either check fails the build, unless it is listed below with the reason a stack may
still create it and where the gap is tracked. Each exception names its types one by one. A new type is
never covered by an old exception. An exception that no longer applies also fails the build until it
is removed, so the list cannot go stale. There is no other allowlist.

## Breadth gaps

The gate runs one way: from CloudFormation types to shim services. The other direction is a ranked
list, not a gate. These are services the shim serves that no CloudFormation type can create here. A
template that declares one of their resources is refused, although the API serves it.

## How the registry is built

Each fact is read from the code that implements it. Only the AWS facts and the exceptions are kept by
hand.

| Source | What it records | How |
|---|---|---|
| [`probe/registry/cfn-types.json`](../probe/registry/cfn-types.json) | every CloudFormation type the engine knows: mapping status, backing kind, create translator, deployable | read from the mapping table and translator dispatch by `cfn/coverage_registry_test.go` |
| [`probe/registry/shim-router.json`](../probe/registry/shim-router.json) | every signing name the aws-shim router serves, its handler, the operations it dispatches, the ones it recognizes only to refuse | read from the router table in `main.go` and each handler's code by `console-api/cmd/aws-shim/coverage_registry_test.go` |
| [`probe/shim-services.yaml`](../probe/shim-services.yaml) | each service's proof: the live probes that show it working (`sigv4` joins it to the router) | hand-kept, cross-checked against `probe/` and the router |
| [`probe/registry/coverage.yaml`](../probe/registry/coverage.yaml) | AWS facts (which API serves a namespace; which calls read a type, where the default does not find them) and the exceptions | hand-kept |
| [`probe/registry/registry.json`](../probe/registry/registry.json) | the join: one row per type, one per signing name, the breadth ranking | generated by [`probe/shimgen.py`](../probe/shimgen.py) |

`probe/shimgen.py` refreshes the two Go-read halves when Go is on `PATH`, then rewrites every generated
block on this page, in [`cloudformation.md`](cloudformation.md), in [`aws-shim.md`](aws-shim.md) and in the
README. `probe/shimgen.py --check` (CI) fails in these cases:

- a block or `registry.json` is stale;
- `shim-services.yaml` disagrees with the router;
- the gate fails;
- a hand-written table in `cloudformation.md` claims more than the code does.

The cfn and console-api test jobs fail if a Go-read half is stale.
