# The customer surface

open-infra's customer is an AWS user, not a Kubernetes operator. Everything a customer can reach — a
resource type and each of its properties, a console API route, a console screen, an AWS API — is in AWS's
terms: an AWS service's action on an AWS ARN, decided by IAM policy, the same question at every door. This
page is the inventory of that surface. It is generated from the code (`probe/registry/customer-surface.json`,
by `probe/shimgen.py`), and CI fails when a capability a customer can reach has no AWS-shaped entry.

## How a capability is classified

- **AWS-shaped** — an AWS service's action on an AWS ARN, as AWS names them (`s3:CreateBucket` on
  `arn:aws:s3:::<bucket>`, `lambda:UpdateFunctionCode` on a function). An AWS policy written for the AWS
  analog means the same here.
- **Platform extra** — a capability AWS has no analog for, with its own AWS-style API: the service prefix
  `openinfra` (`openinfra:CreateDataFlow` on `arn:aws:openinfra:<region>:<account>:dataflow/<name>`).
  `AdministratorAccess` and `PowerUserAccess` cover it, and `ReadOnlyAccess` its reads. One exists only on
  the operator's say-so, recorded in `probe/registry/surface.yaml`.
- **Operator-only** — the platform's own machinery (pods, nodes, Secrets, namespaces, the composite
  resources): `openinfra-operator:<Action>`, which only an Allow naming it (`AdministratorAccess`'s `*`)
  grants, and only in the management account. A member account's principals never reach it.
- **Removed** — withdrawn from the customer surface because it could not be said in AWS's terms.

## Kubernetes is not a customer surface

A tenant has no Kubernetes access. Its principals reach the platform through the AWS APIs and the console,
and every door turns what they ask into an AWS action first:

- **The API server accepts no IAM credential.** An IAM principal's access keys, its console session and the
  token `aws eks get-token` makes from them are not Kubernetes identities. The kubeconfig that
  `aws eks update-kubeconfig` writes names the cluster, and the API server refuses its token.
- **The console's resource API** (`/api/k8s`, `/api/watch`) authorizes each request as the AWS action the
  kinds table maps it to — a resource type's own action on its ARN — before it is forwarded. Any other
  Kubernetes object is operator-only (`openinfra-operator:*`), and a request the table cannot map is refused.
- **The console and the aws-shim act on the API server as the caller** only through impersonation held to
  the platform's `openinfra:*` identities (never `system:masters`; the shim never as root), and the
  authorization webhook decides an account's principal from its compiled IAM policy alone.

What proves it: the console's `TestTenantKubernetesAccessIsRefused` (`console-api/cmd/server`) — no
principal of an account, whatever its policy, reaches a raw Kubernetes object through the console's
resource API or the watch stream, and a member account's administrator is refused the operator's surface;
`TestConsoleProxy_MapsKubernetesRequestsToAWSActions` and `TestConsoleGate_NoPolicyIsDeniedEverywhere`;
the proxy's own `Impersonate-*` stripping (`console-api/internal/proxy`); the impersonation ceilings
(`test/render`); the webhook's `TestWebhook_AccountPrincipalsUseTheIAMCorpus`. Live:
`probe/iam-no-policy.sh`, and `probe/aws-shim-eks-tenant-refused.sh` (the EKS kubeconfig refused by the
API server, the console's raw objects refused), which awaits its first live run.

## Adding a capability

A new resource type, property, route, screen or AWS API is registered by the code that serves it, and the
gate (`python3 probe/shimgen.py --check`, in CI) names each one the committed registry does not list yet:

1. Give it its AWS shape in code: a resource type's row in the kinds table
   (`console-api/internal/awsaction/table.go`), a route's IAM action where it is registered
   (`console-api/cmd/server/routes.go`), an AWS API's actions where it authorizes.
2. A screen names its service in `probe/registry/surface.yaml`; a platform extra, an operator-only kind and
   a property in Kubernetes vocabulary carry the ruling that allows them there.
3. Run `probe/shimgen.py` (it re-reads the code's halves with Go and rewrites the registry and this page),
   review what it registered, and commit it with the change.
